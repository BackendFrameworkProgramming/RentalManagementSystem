6차 (5/3)AI 교차 검증
Repository 쿼리 최적화 + 캐스팅 버그 수정
Repository 쿼리 메서드 추가
findAll() + Java stream filter로 데이터 필터링
findAllByIsDeletedFalse(pageable), findByIdAndIsDeletedFalse(id) 등 Repository에 쿼리 메서드 선언
AI(Claude Opus): "findAll()로 전체 데이터를 메모리에 올린 후 필터링하면 성능 문제. DB 레벨에서 필터링해야 한다"
배치 API 캐스팅 수정
List<Long> deviceIds = (List<Long>) body.get("deviceIds") — ClassCastException 발생
((List<?>) body.get("deviceIds")).stream().map(o → ((Number) o).longValue()) 방식으로 안전 변환
AI(Gemini): "JSON 배열의 숫자는 Integer로 파싱되는데 Long으로 직접 캐스팅하면 런타임 에러"
BiometricData에 is_deleted 추가
BiometricData Entity에 is_deleted 필드 없음
is_deleted 필드 추가 + findAllByIsDeletedFalse() 메서드 추가
AI(Sonnet): "다른 테이블은 전부 is_deleted가 있는데 BiometricData만 없다"
@Transactional 명시
팀원 프롬프트에 @Transactional 관련 안내 없음
팀원3(임대/AS) 프롬프트에 "@Transactional(rollbackFor = Exception.class) 반드시 명시할 것" 추가
AI: "상태 변경을 수반하는 메서드에서 checked exception을 throw하면 롤백이 안 된다"
